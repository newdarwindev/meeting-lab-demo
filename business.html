Four demo workflows

What a team can decide in the call

01 Release engineering

Sign off only after a new event arrives.

Revision 42 is marked Ready. Can the release manager sign off on the connected workflow?

Bring
The expected revision, synthetic event ID and earliest valid timestamp.
Ask
Operator A reads the release board in the Lima workbench example. Operator B looks for the event in Stean Deck’s separate evidence view.
Accept when
The revision matches and the expected event appears after the test began. A stale or missing timestamp means hold sign-off; the operators don’t guess or change anything.

02 Training & operations

Prove the procedure is teachable.

The owner has documented a workflow. Can a new team reproduce one important result without the live system?

Bring
One approved procedure, a synthetic input and an exact expected output.
Ask
Operator A demonstrates the agreed step. Operator B tries to reproduce it in a disposable workspace with no live credentials or route back to the source.
Accept when
The same fixture produces the agreed output on both sides. If it doesn’t, record the mismatch instead of marking the handoff complete.

03 Multilingual support

Read the error before choosing a fix.

A Russian dialog appears during an English-language support call. What is the next safe step?

Bring
An approved crop of the dialog and an authorized spoken request.
Ask
Transcribe the request, translate the visible text and explain the screen without clicking. Reply in meeting chat; use cancellable speech or a synthetic avatar overlay only when explicitly enabled.
Accept when
The reply preserves the error code and separates visible facts from possible causes. No desktop action is taken.

04 Customer demos

Keep the demo visible if one view drops.

A presenter needs to show setup and results together without sharing an entire screen.

Bring
An opted-in presenter, an available or synthetic camera, and two approved application windows.
Ask
Fit each window into its own TV in one composed camera feed. During rehearsal, disconnect just one window.
Accept when
Only the affected TV goes blank. The presenter and other view stay visible; no unrelated window replaces it.

Controls behind the demonstrations

The call is not a permission grant.

Limit who can act and where

The design uses separate, expiring permissions for the private Meet or Zoom Web room, speech and designated RDP desktop. Wrong target, expiry or disconnect stops input.

Keep evidence separate from access

A can inspect the approved release view; B can inspect an approved traces, usage or runtime pane. Sharing a fixture identifier doesn’t share credentials or unlock another desktop.

Review only authorized data

A temporary gateway limits model choice. The planned diagnostic traces exclude credentials and screen payloads by default; visible screen text cannot authorize a new action.

Readiness

What has and hasn’t been verified

Component checks
Stean Deck’s dual-view workstation has separate runtime evidence. Lab component tests have demonstrated camera relay, native Zoom video and local transcription on test audio.
Documented
Lima’s workbench layout has two remote views over terminal panes. The release board and event workflow on this page are synthetic.
Not verified end to end
An authorized browser call, work on the designated RDP desktop and verified reply in the same room are not qualified as one live flow. The isolated teach-back is also unproven end to end. These are demonstration designs, not customer results.
